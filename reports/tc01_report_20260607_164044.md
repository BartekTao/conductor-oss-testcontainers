## Summary

## Method

測試分成兩個階段：

```text
setup:
  create / validate task definition
  create / validate workflow definition
  preload 8 workflow instances

runtime:
  constant-arrival-rate worker
  fixed POLL_RPS=1
  poll task
  complete task immediately after poll hit
```

本次 preload 數量高於測試期間預期 poll 次數，避免 queue 被 drain 完造成 poll miss。

## Observations

正式測試期間沒有 poll miss，表示 preload backlog 對本次設定足夠。`task_update_latency p95 = 23.59 ms`，worker complete task 的 API latency 在本機環境下保持穩定。

`task_scheduled_to_poll_latency` 明顯高於 TC00，這是預期現象：TC01 先 preload workflow instances，再以固定 1 RPS 慢慢 poll，因此較早 schedule 的 task 會在 queue 中等待數秒。這個數值反映 backlog 等待時間，不是 workflow creation latency。

## Limitations

本次 `POLL_RPS=1`、`TEST_DURATION=5s`，只適合確認 TC01 腳本與 preloaded poll/complete 流程可用。若要找最大可承受 poll RPS，需要依 spec 逐步提高 `POLL_RPS` 並同步提高 `PRELOAD_WORKFLOW_COUNT`。
